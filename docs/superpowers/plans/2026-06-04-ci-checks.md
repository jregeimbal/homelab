# CI Checks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add automated CI checks for YAML linting, K8s manifest validation, secret scanning, and JSON linting.

**Architecture:** Single GitHub Actions workflow with sequential checks and pre-commit hooks for local development. CI uses Docker-based tooling to avoid runtime dependencies.

**Tech Stack:** GitHub Actions, yamllint, kubeconform, gitleaks, Python 3

### Task 1: Create YAML lint config (`.yamllint`)

**Files:**
- Create: `.yamllint`

- [ ] **Step 1: Create `.yamllint` config**

Create the file with the following content:

```yaml
extends: default

rules:
  line-length:
    max: 160
    level: warning
  truthy:
    check-keys: false
  indentation:
    spaces: 2
  comments:
    min-spaces-from-content: 1
```

Key rules:
- `line-length`: 160 chars max, warned (not error) to avoid nitpicking
- `truthy`: allows `true`/`false` as bare values in K8s manifests without quoting
- `indentation`: 2 spaces, matching K8s convention
- `comments`: requires 1 space between content and inline comments

- [ ] **Step 2: Verify config works**

Expected: PASS (no errors, this file is simple)

Run: `yamllint -c .yamllint flux/apps/hermes-jon.yaml`
Expected: PASS (this is a complex file, should have no issues with our rules)

### Task 2: Create secret scanning config (`.gitleaks.toml`)

**Files:**
- Create: `.gitleaks.toml`

- [ ] **Step 1: Create `.gitleaks.toml` config**

Create the file with the following content:

```toml
[allowlist]
description = "Global allowlist"
paths = [
    '''\.pre-commit-config\.yaml$''',
    '''secrets/encrypted/.*''',
    '''venv/.*''',
    '''images/.*''',
    '''docs/.*'''
]
```

This excludes:
- `.pre-commit-config.yaml` — contains repo URLs that gitleaks may flag
- `secrets/encrypted/` — sealed secrets are encrypted, not plaintext
- `venv/` — Python virtual environment
- `images/` — binary images (in .gitignore but just in case)
- `docs/` — documentation files

- [ ] **Step 2: Verify config works**

Run: `gitleaks detect --source . --config .gitleaks.toml --verbose`
Expected: No secrets found (exit code 0)

If gitleaks is not installed, skip this step — CI will validate the config.

- [ ] **Step 3: Commit**

```bash
git add .gitleaks.toml
git commit -m "chore: add gitleaks config for secret scanning"
```

### Task 3: Create pre-commit hooks config (`.pre-commit-config.yaml`)

**Files:**
- Create: `.pre-commit-config.yaml`

- [ ] **Step 1: Create `.pre-commit-config.yaml`**

Create the file with the following content:

```yaml
repos:
  - repo: https://github.com/adrienverge/yamllint.git
    rev: v1.37.1
    hooks:
      - id: yamllint
        args: ["--config-file", ".yamllint"]
        types: [file, yaml]
        files: \.(yaml|yml)$
        exclude: \.pre-commit-config\.yaml$

  - repo: https://github.com/pre-commit/pre-commit-hooks
    rev: v5.0.0
    hooks:
      - id: check-json
        files: \.json$
        types: [file]

  - repo: https://github.com/gitleaks/gitleaks.git
    rev: v8.21.2
    hooks:
      - id: gitleaks
        args: ["--config", ".gitleaks.toml"]

  - repo: local
    hooks:
      - id: kubeconform
        name: kubeconform
        entry: kubeconform
        language: system
        args:
          - "-summary"
          - "-k"
          - "-schema-location"
          - "https://raw.githubusercontent.com/datreeio/CRDs-catalog/main/"
        files: ^flux/.*\.yaml$
```

Key design decisions:
- yamllint excludes `.pre-commit-config.yaml` to avoid linting the hook config itself
- `check-json` from pre-commit-hooks validates all JSON files
- kubeconform uses `-k` to skip unknown resource types (Flux HelmReleases, Kustomizations)
- kubeconform uses `language: system` — requires `kubeconform` in PATH (install via `brew install kubeconform`)

- [ ] **Step 2: Verify hooks work**

Run: `pre-commit run --all-files`
Expected: All hooks pass

If pre-commit is not installed, install it first: `brew install pre-commit`

### Task 4: Create GitHub Actions CI workflow (`.github/workflows/ci.yml`)

**Files:**
- Create: `.github/workflows/ci.yml`

- [ ] **Step 1: Create CI workflow**

Create the file with the following content:

```yaml
name: CI

on:
  pull_request:
  push:
    branches: [main]

jobs:
  ci:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 2

      - name: YAML lint
        run: |
          docker run --rm -v $PWD:/workdir \
            adrienverge/yamllint:latest \
            -c /workdir/.yamllint \
            --format parsable \
            $(git ls-files '*.yaml' '*.yml' | grep -vE 'pre-commit-config\.yaml$')

      - name: K8s manifest validation
        run: |
          docker run --rm -v $PWD:/workdir \
            ghcr.io/yannh/kubeconform:latest \
            -summary -k \
            -schema-location "https://raw.githubusercontent.com/datreeio/CRDs-catalog/main/" \
            $(git ls-files 'flux/**/*.yaml')

      - name: Secret scanning
        uses: zricethegav/gitleaks-action@v1.2.0
        with:
          config: .gitleaks.toml
          verbose: true

      - name: JSON lint
        run: |
          python3 -c "
          import json, glob, sys
          errors = []
          for f in glob.glob('assets/**/*.json', recursive=True):
              try:
                  with open(f) as fh:
                      json.load(fh)
              except (json.JSONDecodeError, FileNotFoundError) as e:
                  errors.append(f'{f}: {e}')
          if errors:
              for e in errors:
                  print(e)
              sys.exit(1)
          "
```

Key design decisions:
- Single job, sequential steps with fail-fast (default behavior)
- YAML lint uses Docker to avoid installing yamllint
- K8s validation uses Docker with `-k` to skip Flux custom resources
- Secret scanning uses the official gitleaks GitHub Action with our config
- JSON lint uses Python 3 (available on ubuntu-latest) to validate all JSON in `assets/`
- `fetch-depth: 2` for efficient checkout
